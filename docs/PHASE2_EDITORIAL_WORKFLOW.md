# Phase 2 内容工作流与分类决策

日期：2026-11-10。新内容版本 0.3.0；偏好探索规则 0.1.0。

## 历史与新增层

原始 479 项、稳定 ID、17 个目录分类、v0.2 草稿及分类审计保持不变。`data/knowledge/history-lock.json` 保存基线提交和 LF 归一化 SHA-256；校验在跨平台检出时忽略换行差异，不允许文本内容变化。新定义不写回旧文件，也不删除旧证据。详情页可展开旧记录。

新增层位于 `data/knowledge/cards.json`，编辑源为 `scripts/author-knowledge.mjs`。该脚本只把逐条撰写的内容序列化为 JSON，不调用模型、抓取服务或根据名称自动生成事实。重新运行后须人工复核 diff，不应把生成成功当内容已审核。

## 分类审查

本版用主要互动目的或角色对来组织工作原型；允许重叠，不声称互斥完备。20 个核心原型覆盖浪漫伴侣、约会、朋友、选择性家人、室友、共同育儿、生活照料、学习协作、研究协作、导引、技能交换、同事、项目合作、创业、委托工作、买卖、教学、邻里、社区互助和内容共创。

核心原型与旧 20 个拟议原型族是不同版本的组织方案，不强行宣称一一对应。保留旧族值，避免暗中修复或掩盖 321 项历史映射缺口。

## 证据身份

1. **来源支持命题**：`sources.json` 记录 URL、版本、定位、查询日期、具体支持内容、访问深度和适用限制。网页读取与独立审核分开。7 项相关页面读取，1 项共同育儿论文仅元数据／摘要线索；全文验证页缺口明示。
2. **可追溯工作定义**：当前全部 60 张卡的正文、场景和协商提示属于这一层。情境为虚构；冲突不声称普遍发生；法律责任不由名称推定。29 张有相关背景来源，31 张没有独立外部来源。
3. **待验证假设**：字段存在，本版未填入研究假设。编辑推荐模板是规范性阅读安排，单独存在 `src/lib/assessment.ts`，不是知识事实或已证实的个人结论。

**独立人工审核 0 张。** AI 来源核对、Zod 校验、测试通过均不能提升为独立人工或专家审核。不要添加虚构审核人。

## 批次与复核步骤

- P2-01：20 个核心原型，逐项写定义、范围、虚构情境、角色、需要、互动、情感时间资源、边界、误解、冲突、相邻差异与变化；额外提供独立情境拆解和扩展讨论。
- P2-02：40 张基础卡，刻意包括变体、场景、结构、复合和状态，避免把数量当成独立原型数量。
- 后续每批建议 10–20 张：先选择 ID 与分类问题，再检索一手／权威资料；登记源与缺口；撰写工作定义；运行校验；由具名审核者复核关键命题、边界与链接，记录日期和修改理由后再变更审核状态及 schema。
- 正文不能仅粘贴来源摘要；来源不能仅贴概览 URL。每个来源应能回答支持了哪一句、没有支持什么。法律或专业服务条目先明确法域／机构范围，不拼接通用法律保证。
- 内容编辑检查：不要用“通常”“必然”伪造发生率；区分角色与权力、同意与资格、定义与价值判断；近义词保留稳定 ID，不为凑类别拆成独立原型。

## 重现与验收

```sh
node scripts/author-knowledge.mjs
npm run validate:data
npm run test:unit
npm run typecheck
npm run lint
npm run build:pages
npm run test:pages
```

`validate:data` 先验证历史层，再验证新内容。覆盖报告由 `scripts/validate-knowledge.ts` 生成，始终分列基础完整度、深度内容、来源读取和独立审核。字数／字段校验只是最低结构检查，不保证内容质量。浏览器还需检查长文阅读、链接、筛选和实际三视口体验。
