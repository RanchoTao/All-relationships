# 关系罗盘：匿名挂出需求

罗盘仍在浏览器内答题。只有主动开启表单并点「确认挂出」才会提交：当前最多三张可挂出的候选卡编号、主选卡、底线、城市、可选公开描述、联系方式和两项确认。候选按当前卡堆的显示顺序读取；卡堆不足时用已留下的可挂出卡补足，不凭空补齐三张。仅供了解的卡和直接描述性亲密偏好的卡不会被带入。原始答案以及罗盘里的自填内容不会随表单发送。

这里的「匿名」指不在网站上公开身份或需求。运营者能看到提交内容，联系潜在双方时只展示用户允许展示的匿名描述，分别征得同意后才交换联系方式。数据库不提供公开需求列表。

## 配置与运营

1. 先使用独立测试 Supabase 项目。在 SQL Editor 执行 [listings.sql](../supabase/listings.sql)。这是单次建表；遇到同名表会回滚，不要直接覆盖已有项目数据。确认 Data API 暴露 `public` schema。
2. 在 [listing.js](../public/compass/listing.js) 顶部填写 HTTPS 项目地址、`sb_publishable_…` 公钥和由运营者实际接收删除请求的邮箱。三个值未配齐之前无法提交。公钥可以出现在静态网站里；不要填写管理密钥。
3. 确认选定的项目地区与「境外存放」说明一致，后台人员只有指定运营者，且运营者能在收到邮件后 7 天内处理删除。账号权限和删除处理是运营设置，不能由表单替代。
4. 正式接入前用下面的合成验收复测。蜜罐和 60 秒冷却只限制浏览器内的重复提交，不能约束直接 REST 请求；如果需要防止公网刷写，需在启用真实收集之前加服务端限流或验证，并关闭可绕过该验证的直插入口。
5. 原始罗盘单文件更新时，保留 `#compass-listing` 挂载点和 `./listing.js` 脚本。若生成器改变 `DATA.cards`、结果卡堆或已选卡的结构，更新适配器并重新跑浏览器测试。

SDK 仅在第一次有效提交时加载，为固定版本 2.119.2 的浏览器构建，使用 SRI 校验。HTML 只加挂载点和脚本；CSS 由独立脚本引入。

## 验收步骤与结果

| 验收项 | 操作 | 结果 |
| --- | --- | --- |
| 正常提交 | 在本地 PostgreSQL 19 / PostgREST 16.6 应用 SQL，执行 `node scripts/test-listings-rest.mjs`，用数据库所有者核对合成记录；另外用实际 Supabase JS SDK 和本地匿名 JWT 插入 | 两次插入均为 HTTP 201，不返回记录。数据库所有者能看见合成记录，默认 ID、创建时间与 `new` 状态正确。 |
| 匿名权限 | 用同一匿名 REST 入口执行 GET、PATCH、DELETE，额外测试要求返回记录的 POST | 均为 HTTP 401，记录未被修改或删除。 |
| 无效载荷 | 分别关闭同意、关闭成年、写非 `new` 状态、提交三条底线；另外验证超长字段、底线空元素、无效主选和后台字段 | 以上请求均为 HTTP 401。 |
| 三种屏幕和表单 | Playwright 使用桌面、平板、手机视口，检查候选次序、默认选项、字段校验、隐私展开、蜜罐、成功状态与刷新后冷却 | 6 项新用例通过，浏览器请求使用合成表单和测试端点。 |
| 罗盘回归 | 进入罗盘、实际回答、打开结果、留下一张卡、打开和关闭表单，再检查选卡 | 三种视口均通过；整套浏览器回归 43 项通过、2 项按原配置跳过。 |

仓库数据校验、30 项单测、类型检查和 lint 通过。仓库当前锁定的 Next.js 16.4.1 生成了 488 个页面，但 `npm run build:pages` 最后在依赖安全检查返回非零；浏览器测试使用生成的静态文件。本次没有改动仓库依赖。

托管 Supabase 项目和 Dashboard 未连接，没有写入真实数据。待测试项目可用时，在该项目执行 SQL 后，按以下方式用实际 publishable 公钥复验。此脚本包含一次真实 INSERT，只允许显式指定一次性测试项目；不要对生产项目运行。

```powershell
$env:LISTINGS_TEST_URL = "https://<test-project>.supabase.co/rest/v1"
$env:LISTINGS_TEST_PUBLISHABLE_KEY = "sb_publishable_<test-project-key>"
$env:LISTINGS_TEST_DISPOSABLE_PROJECT = "yes"
node scripts/test-listings-rest.mjs
```

随后在 Dashboard 的 `public.listings`（或 SQL Editor）查验脚本打印的 `@example.invalid` 合成邮箱记录，确认状态为 `new`，核对没有其他测试变更，再删除这条合成记录。
